# 空き枠算出・同時予約制御の仕様

実装場所: RexCarte `backend/app/services/availability.py`（算出）と `services/booking_rules.py`（判定）。
顧客向けの空き枠表示と予約確定時の検証は、必ず同じ判定関数を使う。

## 1. 入力

| 入力 | 説明 |
| --- | --- |
| `store_id` | `web_booking_enabled` かつ `is_active` の店舗のうち、**ログイン中の顧客が顧客として登録されている店舗**（それ以外は 404） |
| `date` | JST の日付 |
| `ticket_plan_id` | 必須（予約はチケットを使う）。`web_bookable` かつ `is_active` のプラン |
| `staff_id` | 省略時は指名なし（候補スタッフ全員） |
| `now` | 現在時刻（テストで固定できるよう引数で受け取る） |

## 2. 所要時間

- チケットプラン: `ticket_plans.duration_minutes`

## 3. 算出手順

### 3.1 日付単位で空配列を返す条件（早期終了）

1. 店舗の `business_hours` が未設定、またはその曜日が定休日（`null`）
2. その日が営業終了済み（`daily_closings` に行がある）
3. `date` が「今日（JST）」より前、または `今日 + max_advance_days` より後

### 3.2 候補スタッフ

- `staff_id` 指定時: そのスタッフのみ（`web_bookable`・`is_active`・同じ店舗でなければ 404）
- 指名なし: 店舗の `web_bookable` かつ `is_active` なスタッフ全員
- 各スタッフの稼働時間帯:
  - `weekly_shift` が設定済み: その曜日の `open`〜`close`。休日（`null`）なら候補から外す
  - `weekly_shift` が未設定: 店舗の営業時間に従う
  - さらに店舗の営業時間と重なる部分に限定する（店舗の開店前・閉店後にはみ出すシフトは切り詰める）

### 3.3 開始時刻の候補

- 店舗の開店時刻から `slot_interval_minutes` 刻みで、閉店時刻 − 所要時間まで並べる。
  例: 営業 9:00〜20:00、刻み 30 分、所要 90 分 → 9:00, 9:30, …, 18:30
- 開始時刻 `< now + min_lead_minutes` の候補は除外する。

### 3.4 各候補の判定

候補の開始時刻 `s`、終了 `e = s + 所要時間` について、次をすべて満たすスタッフが 1 人以上いれば枠として返す。

1. `s` と `e` がスタッフの稼働時間帯に収まる（`e` がちょうど終了時刻は可）
2. そのスタッフの確定予約（`status = confirmed`）と時間帯が重ならない（`[s, e)` と `[start_at, end_at)` が交差しない）

- 既存予約は「店舗 × その日 × 候補スタッフ」の確定予約を 1 クエリで取得し、メモリ上で判定する。
- 返すのは開始時刻のみ。どのスタッフが空いているか、なぜ空いていないかは返さない。

### 3.5 指名なしの担当割り当て（予約確定時）

確定時に `s` が空いているスタッフのうち、以下の順で選ぶ（`01-requirements.md` 4章の既定値）。

1. その日の確定予約件数が少ない
2. 同数ならスタッフ名の昇順（決定的にしてテストしやすくする）

## 4. 日付ごとの可否（カレンダー用）

`/availability/days` は `from`〜`to`（最大 `max_advance_days` 日）の各日について §3 を実行し、枠が 1 つ以上あるかを返す。
1 日ずつクエリしないよう、期間内の確定予約・営業終了日をまとめて取得する。

## 5. 予約確定時の検証と同時予約制御

1. トランザクション開始
2. 対象 `customer_tickets` 行を `SELECT ... FOR UPDATE` でロックし、`bookable_count` と有効期限を検証
3. `booking_rules.find_violations(mode="customer")` で §3 と同じ条件を再検証（`now` はリクエスト時刻）
4. 指名なしなら §3.5 で担当を決める
5. INSERT
6. コミット。**排他制約違反（`IntegrityError`）なら 409** で返し、指名なしの場合は別スタッフで 1 回だけ再試行する

RexCarte の DB の排他制約（同じスタッフの予約時間帯の重なりを禁止）が最終防衛線。アプリの事前チェックは「分かりやすいエラーを早く返す」ためのもので、これだけに頼らない。

## 6. キャンセルの判定

- 本人（`reservations.customer_account_id` または紐付いた顧客レコード）の予約であること
- `status = confirmed`
- `now <= start_at − cancel_deadline_hours`
- その日が営業終了済みでないこと

## 7. テストケース（RexCarte pytest で網羅する）

| # | ケース | 期待 |
| --- | --- | --- |
| A1 | 営業 9:00〜20:00、刻み 30 分、所要 60 分、予約なし | 9:00〜19:00 の 21 枠 |
| A2 | 定休日の曜日 | 空配列 |
| A3 | 営業終了済みの日 | 空配列 |
| A4 | 営業時間未設定の店舗 | 空配列 |
| A5 | 指名スタッフが休日 | 空配列 |
| A6 | シフト 11:00〜20:00 のスタッフを指名 | 11:00 開始から |
| A7 | 10:00〜11:00 に確定予約あり（所要 60 分） | 10:00 と 9:30・10:30 開始が消える |
| A8 | キャンセル済み・無断キャンセルの予約 | キャンセルは枠を塞がない。無断キャンセルは確定ではないので塞がない |
| A9 | 指名なし、2 人中 1 人だけ埋まっている時間 | 枠として返る |
| A10 | `now` から 2 時間以内の開始 | 除外 |
| A11 | `max_advance_days` を超える日付 | 空配列 |
| A12 | シフト未設定のスタッフ | 店舗の営業時間で判定 |
| A13 | 非公開チケットプラン / 非公開スタッフ / Web 予約 OFF の店舗 / 顧客として登録されていない店舗 / 未ログイン | 404（未ログインは 401） |
| A14 | 予約できる先の期間（既定 60 日）の全体を 1 回の日付ごとの可否で問い合わせる（カレンダー用） | 200。期間が上限を超えると 422 |
| B1 | 同じ枠へ同時に 2 件予約（スレッド 2 本） | 1 件だけ成功、もう 1 件は 409 |
| B2 | 表示後に店舗が同じ枠に電話予約を入れた | 顧客の確定は 409 |
| B3 | チケットの残回数 1・未来の予約 1 件あり | 予約不可（409） |
| B4 | 同じプランのチケット 2 枚（期限の近い方は予約可能回数 0） | 期限の遠い方で予約される |
| B5 | 予約日がチケットの有効期限後 | 409 |
| B6 | 指名なしで割り当て候補が同数 | 名前順で決定 |
| C1 | キャンセル期限内 / 期限後 | 成功 / 409 |
| C2 | 他人の予約をキャンセル | 404 |
| C3 | 顧客トークンでスタッフ用 API | 401 |
| C4 | スタッフトークンで顧客用 API | 401 |
| C5 | ルール違反のレスポンス本文にスタッフ名・理由が含まれない | 共通文言のみ |
