# 要件定義

## 1. 登場人物

| 人物 | 使うもの | 主な操作 |
| --- | --- | --- |
| 顧客（店舗に登録済みの人のみ） | RexBook（スマートフォン中心） | ログイン、店舗の切り替え、保有チケットでの予約、日時の選択、キャンセル、保有チケット・予約の確認 |
| 店舗スタッフ・管理者 | RexCarte（既存） | Web 予約の受付設定、チケットプランの公開・チケットの付与（店頭購入の反映）・スタッフの設定、Web 予約の確認と来店処理 |

## 2. 機能要件（顧客側）

**前提**: このアプリは、店舗に**顧客として登録済み**（店舗の顧客レコードに同じメールアドレスがある）の人だけが使える。**ログインしていなければ、店舗・チケット・空き枠を含めて何も表示しない。**

### 2.0 導入先の表示（事業者設定）

- FR-Z1 ヘッダーとブラウザのタブのタイトルに、導入先の事業者名とアイコンを表示する（RexCarte の事業者設定。ログイン前の画面にも出す。未設定・取得できないときは「RexBook」）。
- FR-Z2 顧客に送るメール（ログインコード・予約確定・予約キャンセル）の送信者名・返信先・件名・本文は、RexCarte の事業者設定で変えられる。RexBook 自身はメールを送らず、設定も持たない。

### 2.1 顧客認証

- FR-A1 メールアドレスを入力すると、そのメールアドレスが店舗に顧客として登録されている場合に限り、6 桁のワンタイムコードをメールで送る。コードの有効期限は 10 分。
- FR-A2 コードを入力するとログインできる。同じコードでの試行は 5 回まで。失敗が続いたらコードを無効にする。
- FR-A3 登録済みかどうかにかかわらず、同じ画面・同じ文言（「登録されているメールアドレスの場合、コードを送信しました」）にする。未登録のメールアドレスには送信せず、どんなコードでもログインできない（メールアドレスの登録有無を推測させない）。
- FR-A4 コード送信には回数制限を設ける（同じメールアドレス・同じ接続元あたり）。
- FR-A5 使える顧客は「有効な顧客レコードで、店舗が有効かつ Web 予約を受け付けている」もの。店舗が顧客を無効にした・Web 予約をやめた場合は、以降ログインしても使えない。
- FR-A6 ログイン状態は一定期間（7 日）で失効する。ログアウトできる。
- FR-A7 未ログインで画面を開くと、戻り先つきでログイン画面へ誘導する。

### 2.2 顧客レコードとの紐付け

- FR-C1 RexCarte の顧客は店舗ごとに管理されている。顧客アカウント（メールアドレス単位）は、店舗ごとの顧客レコードに紐付く。**紐付けはログインのたびに、メールアドレスの一致で行う**（ログイン後に別の店舗へ顧客登録されても、次のログインから使える）。
- FR-C2 顧客レコードは店舗が作る。**予約時に顧客レコードを新しく作ることはしない**。登録されていない店舗では予約できない。
- FR-C3 電話番号・氏名だけが一致するレコードには紐付けない（誤紐付けで他人の来店履歴・チケットが見えるのを防ぐ）。
- FR-C4 同じ店舗に同じメールアドレスの顧客が複数いる場合、1 アカウントが紐付くのは古い 1 件だけ。重複は店舗側で整理する。
- FR-C5 氏名・フリガナ・電話番号は店舗が顧客レコードで管理し、**お客様自身では変更できない**（プロフィールの編集画面・API は持たない）。ログインのたびに顧客レコードの内容に揃える。電話番号が未登録の顧客はログインできるが予約できず、店舗への問い合わせを案内する。

### 2.3 ホーム（予約状況）と店舗の選択

- FR-H1 ログイン後の最初の画面（予約トップ）を、上から ①お名前と予約ボタン ②今後のご予約（横スクロールのカード）③予約カレンダー ④マイチケット の順に構成する。お名前・マイページはヘッダーに出さない。
- FR-H2 予約カレンダーは、選んでいる店舗の予約（確定・来店済み）がある日を、今後・過去で区別して示し、日付を押すとその日の予約を表示する。キャンセル済みの予約は出さない。
- FR-H3 「予約する」ボタンは必ず「チケットを選択」から始まる（自動でチケットを選ばない）。チケットが無ければ、予約ボタンを出さず「店舗でご購入ください」の案内を出す。マイチケットは「3/8（有効期限 2026/12/20）」（予約に使える回数/購入時の回数）で示し、単発・回数券の区別は表示しない。

- FR-B1 顧客として登録されている店舗（Web 予約を受け付けているもの）だけを扱う。
- FR-B2 複数の店舗に登録されている場合は、店舗をセレクターで切り替えられる（予約トップ・店舗情報・予約）。**予約・保有チケット・予約状況は、選んでいる店舗の分だけ**を表示する。
- FR-B3 店舗情報のページに、店舗名・住所・電話番号・曜日ごとの営業時間を表示する（予約時にあまり見ないため、予約の導線には置かない）。Web 予約で指名できるスタッフ（名前のみ）は日時の画面で選ぶ。

### 2.4 予約の始め方（チケット）

- FR-S1 **予約はすべて、保有チケット（単発 = 1 回のチケット、回数券 = 複数回のチケット）を 1 回分使って行う。** メニューを選んで予約する導線はない。所要時間はチケットプランの 1 回あたりの所要時間で決まるので、予約できる日時から選べる。
- FR-S2 予約ボタンを押すと、持っているチケットの一覧（チケットを選択）から始まる。日時の画面では「チケット変更」で選び直せる。同じプランのチケットは 1 つにまとめて表示する。
- FR-S3 チケットを持たない顧客（使い切り・期限切れを含む）は予約できない。「ご利用いただけるチケットがありません。店舗でご購入ください」と案内する。
- FR-S4 チケットを選び直しても、選んでいた日付・担当は引き継ぐ。所要時間が変わるため、時刻は選び直す。
- FR-S5 チケットは店頭で購入し、スタッフが RexCarte で顧客に付与する（現状）。付与されるとすぐ Web から予約できる。将来は決済を導入してオンライン購入できるようにする（スコープ外）。

### 2.5 日時・担当の選択（空き枠）

- FR-D1 日時の画面で、担当（指名なし＝既定 / 指名できるスタッフ）と日付・時刻を選ぶ。担当を変えると空き枠も変わる。
- FR-D2 日付は、今日から 2 週間分のタブで選べる。**それより先は、月カレンダーで、予約できる先の期間（店舗設定。既定 60 日）まで選べる**。カレンダーで移動できる月は、今日の月から予約できる最後の日の月まで。
- FR-D3 空き枠は RexCarte の予約ルール（営業日・営業時間・スタッフのシフト・既存予約との重複・営業終了日）をすべて満たすものだけを返す。算出方法は `04-availability-spec.md`。
- FR-D4 **予約できない理由は表示しない**。休日・埋まり・時間外を区別せず、「予約できる時刻がありません」とだけ表示する。予約できる時刻が 1 つもない日は、タブでもカレンダーでも選べない表示にする（色だけに頼らず、記号・文字でも示す）。
- FR-D5 日付・担当・カレンダーの月を切り替えても、画面のスクロール位置は変えない。

### 2.6 予約の確定

- FR-R1 確認画面（店舗・チケット・担当・日時・ご利用回数・キャンセル期限）を経て予約を確定する。「予約を確定する」を押しても直ちには確定せず、「この内容で予約を確定します。よろしいですか？」の確認のあと「確定する」で確定する（誤操作防止）。
- FR-R2 確定時にサーバー側で全ルールを再検証する。選んだ枠が他の人に先に取られていた場合は予約せず、共通の文言（「この時間は予約できません。別の日時をお選びください」）を表示して日時選択に戻す。
- FR-R3 同じ枠への同時予約で二重予約が発生しないことを保証する（DB 制約。`04-availability-spec.md` §5）。
- FR-R4 指名なしで予約した場合、担当スタッフは確定時にサーバーが割り当てる（ルールは4章の既定値）。顧客には確定後に担当者名を表示する。
- FR-R5 予約は RexCarte に「確定」ステータス・予約元「Web」で、**紐付いている顧客レコード**に対して登録され、店舗の予約タイムラインにそのまま表示される。
- FR-R6 予約確定時に確認メールを送る。店舗へのご要望（任意）を添えられる。

### 2.7 予約状況・マイチケット（マイページは持たない）

- FR-M1 選んでいる店舗の今後の予約（日時・チケット・担当）をカードで、予約（確定・来店済み）の日を予約カレンダーで示す。カレンダーの日付を押すとその日の予約が見え、詳細でキャンセル期限・キャンセルを扱う。予約トップと同じ内容になるマイページは設けない。
- FR-M2 選んでいる店舗の保有チケット（チケット名・予約に使える回数/購入時の回数・有効期限）を予約トップに表示する。残回数は「未来の確定予約で使う予定の回数」を差し引いた「予約に使える回数」も併記する。

### 2.8 キャンセル

- FR-X1 キャンセル期限（4章の既定値。店舗設定で変更可）までは顧客自身でキャンセルできる。ステータスはキャンセルになり、枠が空く。
- FR-X2 期限を過ぎた予約はキャンセルボタンを出さず、店舗の電話番号を案内する。
- FR-X3 営業終了済みの日の予約はキャンセルできない（RexCarte の締めルール）。
- FR-X4 キャンセル時に確認メールを送る。

### 2.9 チケットを使った予約

- FR-T1 ログイン中の顧客は、その店舗で保有している有効なチケットで予約できる。所要時間はチケットプランの 1 回あたりの所要時間。
- FR-T2 同じプランのチケットを複数持つ場合は、有効期限が近いものを自動で使う（RexCarte の FEFO と同じ）。
- FR-T3 「残回数 − 未来の確定予約で使う予定の回数」が 1 以上のときだけ予約できる（残回数を超える予約を防ぐ）。単発（1 回）は、予約が入っている間は再度予約できない。
- FR-T4 予約日がチケットの有効期限を過ぎる場合は予約できない。
- FR-T5 予約時点では残回数を減らさない。来店（予約の完了）時に RexCarte が消化する（既存仕様）。キャンセルすると使える回数が戻る。

## 3. 機能要件（RexCarte 側に追加）

- FR-K1 店舗設定に「Web 予約を受け付ける」ON/OFF と予約受付設定（空き枠の刻み・直前締切・予約できる先の期間・キャンセル期限）を追加する。
- FR-K2 チケットプラン・スタッフに「Web 予約で公開する」設定を追加する（Web 予約で使うチケットプランに設定する。単発メニューは 1 回のチケットプランとして登録する）。
- FR-K3 予約タイムライン・予約詳細で、Web から入った予約を区別して表示する。
- FR-K4 顧客詳細で、Web 予約アカウントに紐付いているかを表示する。

## 4. 既定値（店舗設定で変更可）

| 項目 | 既定値 |
| --- | --- |
| キャンセル受付期限 | 予約開始の 24 時間前まで |
| 直前予約の締切 | 予約開始の 2 時間前まで |
| 予約できる先の期間 | 60 日先まで |
| 空き枠の刻み | 30 分 |
| 指名なし予約の担当割り当て | その日の確定予約数が最も少ないスタッフ（同数ならスタッフ名順） |
| Web 予約の受け付け | 店舗ごとに ON/OFF（既定 OFF。店舗が設定してから公開） |
| 予約時の通知 | 予約確定・キャンセル時に顧客へメール。店舗への通知は行わない（タイムラインで確認） |

## 5. 非機能要件

| 分類 | 要件 |
| --- | --- |
| 対象端末 | スマートフォン優先のレスポンシブ。最新の iOS Safari / Android Chrome / PC ブラウザ |
| タイムゾーン | JST 固定。DB は UTC 保存（RexCarte と同じ） |
| 認可 | 顧客は自分の予約・自分のチケットのみ参照・操作できる。顧客として登録されていない店舗のデータ（チケット・空き枠を含む）は、存在の有無も分からない（404）。顧客トークンで店舗スタッフ用 API は使えない（逆も不可） |
| 個人情報 | 顧客アカウントが持つのはメールアドレス・氏名・フリガナ・電話番号のみ。エラー文言に他人の情報（スタッフの休日理由など）を含めない |
| 同時実行 | 同じスタッフ・同じ時間帯の確定予約は DB 制約で 1 件に限定する |
| セキュリティ | ワンタイムコードはハッシュ化して保存。コード送信・検証に回数制限。トークンは httpOnly・Secure・SameSite=Lax の Cookie |
| 性能 | 空き枠は「店舗・日付・チケットプラン・スタッフ」単位の 1 リクエストで返す。1 日分の予約を 1 クエリで取得して計算する |
| 可搬性 | Docker Compose だけでローカル起動できる。機密値は環境変数。`.env.example` とシードはダミー値 |
| テスト | 空き枠算出・同時予約・認証・認可は RexCarte 側の pytest で網羅。主要フローは Playwright の E2E |
